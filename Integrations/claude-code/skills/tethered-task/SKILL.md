name: tethered-task
description: Select a Tethered profile, activation rule, and ending mode for this chat.
---

When the user opens Tethered or asks to configure it for this chat, call list_task_profiles and display every returned profile with its controls and maximum duration. Ask the user to select a profile, activation rule, and ending mode. Activation rules are every prompt in this chat, explicit requests only, or user-defined criteria (the model may judge those criteria). Ending modes are end after each reply/task, or intentionally let the session expire. Retain these choices in this conversation only, until changed or cleared; do not write project instructions or global preferences. Never invent profile IDs. Without a chat selection, use Tethered only when explicitly requested and ask which saved profile to use.

For every-prompt activation, begin before handling each subsequent user prompt, including short replies; do not restrict this choice to substantial local work. For criteria activation, apply the user's criteria. Before beginning, check get_session_status. Reuse a still-active session only if its exact session_id was returned to this chat and its profile matches the selection. Never adopt or end another chat's session. If another session is active, explain the conflict and continue without changing it. Start with the selected profile and its maximum_minutes unless the user chose a shorter duration. Record the returned session_id and phase.

In end-after-task mode, end that exact owned session when the reply/task finishes, fails, or is cancelled. In expiration mode, leave it active between prompts; reuse it without extending or resetting its expiration. After it expires, begin a new session on the next matching prompt. An explicit stop ends only this chat's owned session; clearing the selection also disables future activation. When changing profiles while an owned session is active, end it before starting the newly selected profile. Changing ending mode to end-after-task ends an idle owned session. If a call times out, check status before retrying. If the bridge is unavailable or access denied, continue the user's work. These instructions depend on the host's model and approvals, not guaranteed lifecycle hooks; Tethered expires sessions independently. Charging exceptions come only from the saved profile. Never change individual controls or disable heat monitoring, alerts, or fan protection.
